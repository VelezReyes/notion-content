Before we dive in

What is RADAR?

RADAR, Repository for Assets, Decisions, Analysis and Research, is ver+'s new system for categorizing every file we create. One official home per document, easy to find, no duplicates. It works through a single new folder on Drive, called RADAR, where the entire new structure lives.

Start here, the new methodology

This is how we save files now

RADAR replaces ad hoc folders and personal habits with one official home for every file. We produce close to 20,000 files a year. Without a shared structure, that volume turns into noise instead of institutional memory: work ends up outside institutional folders, final versions get duplicated, and the old structure no longer matched how ver+ actually works.

One of the most-asked questions

How to name a file

This works whether or not you use the Drive Finder, so if you'd rather do it manually, you can. Use this format whenever date, status, or version matter:

YYYY-MM-DD_[Object]_[DocumentType]_[Status]_v##

DateYYYY-MM-DD, the day the file was created or last approved.
ObjectThe specific organization, venture, program, or topic the file is about.
Document TypeWhat kind of document it is: Report, Memo, Agreement, Deck, Evaluation, and so on.
StatusWhen relevant: DRAFT, FOR_REVIEW, APPROVED, SIGNED, or SUPERSEDED.
Versionv01, v02, and so on, a running version number.

Avoid names that don't help anyone else identify the file:

finalfinal2lastnewpersonal initials

In a hurry? Open the Drive Finder's Classify tab: describe your file in a sentence and it suggests the folder and the file name. The other tab helps you find existing files quickly. The format above works just as well if you'd rather do it by hand, it's your call.

The routing dictionary

This is the detailed logic behind RADAR: the why behind each block, and every routing question mapped to its official destination, straight from the full Folder Use Guidelines. Use it when the short version on the Guide page isn't specific enough, or when you want to understand the full reasoning.

How folders are located and created

Every object gets exactly one official folder, and its location is decided by what the object is, not by who created it or which area needs it. A new subfolder only gets added when it will hold a recurring set of documents and doesn't duplicate one that already exists, that single rule is what keeps the structure from sprawling over time. Two objects run on their own expanded template instead of this standard path: Democracia+, because it can manage a subportfolio of organizations and may eventually spin off, and Beca Tech, because it needs extra volume rules so thousands of files don't pile up in one place. Everything else follows the rule below.

Inside the tool

How the Drive Finder works

The Drive Finder has two tools that matter most here. Classify answers "where should this go and what should I call it?" for a file you already have. Create Structure builds the real, official folders in Drive for something new, an organization, a program, a policy, a meeting, an OKR year, following this exact Routing Dictionary automatically.

Tool 1

Classify: naming and routing

For a file you already have, in hand right now.

Describe what you're saving, in Spanish, English, or Portuguese, and Classify suggests the destination folder and a consistent file name. Three extra inputs help it narrow down the answer, all optional except the description itself.

FieldWhat it does
DescriptionFree text. "Board meeting minutes for August" or "Fotos del evento de Beca Tech" both work.
ObjectOptional. The organization, program, or topic the file is about.
ContextAuto, or force it: Exploration, Pipeline, Portfolio, Venture, In-house, Institutional.
ThemeAuto, or force it: Education, Democracy, Cross-thematic.

The result shows a recommended location, a suggested file name, a short "why," and a confidence level. When confidence isn't high, it also tells you exactly what would improve it, usually adding the object name.

Ubicación recomendada03_INSTITUTIONAL/00_POLICIES/[Object]/99_Drafts
Nombre sugerido2026-08-21_[Object]_Policy_DRAFT_v01

Example above: description was just "a policy draft," with no object named, hence the medium confidence and the [Object] placeholder in both the path and the file name.

Classify only recommends, it never creates, moves, or renames anything in Drive. Nothing changes until you save the file yourself, at the suggested location.

Tool 2

Create Structure: building real folders

For something new that doesn't exist in Drive yet.

Google Drive doesn't let you duplicate a folder template into a new location the way RADAR needs, so the template folders you see in RADAR are references, not copies to reuse. When you need a genuinely new standard structure, Create Structure builds it correctly instead of you rebuilding it by hand.

Before you start: the first time you use it, RADAR asks for permission to access your Drive and create the folders on your behalf. Accept it to continue, this only happens once.

Choose what you're creating. Each type maps to a fixed spot in the Routing Dictionary.

TypeWhat it's for
Pipeline organizationA new opportunity under evaluation. Sourcing, Screening, and Diligence are subfolders inside the object, advancing a stage never moves the folder.
Venture Building initiativeAn initiative ver+ is building. If its operating model later changes, the complete folder is moved rather than rebuilt.
In-house programA program ver+ operates directly. Includes a restricted participant/beneficiary data folder that needs access configured by hand after creation.
PolicyAn organization-wide policy and its supporting guidance. Policies live only here, use a shortcut if a function needs visibility elsewhere.
Formal governance meetingA Board, Leadership Team, All Team, or Offsite meeting package. Concept Review and Investment Committee are project gates and are never stored here.
Annual OKR cycleOne OKR folder per year. Years are never mixed in the same folder.

Portfolio is intentionally not on this list. When a Pipeline organization is approved, move its existing folder to Portfolio and add the operating subfolders, don't create a new one from scratch.

The fields change depending on the structure type chosen in step 1.

Structure typeFields
Pipeline organization / Venture Building initiativeName* (used exactly as typed, accents/spaces/+/&/hyphens/apostrophes are kept) · Theme* (Education or Democracy only) · Owner (optional, Master Registry) · Country/geography (optional, Master Registry) · Strategic focus (optional, metadata only, never becomes a folder) · Meeting log year* (names the yearly Meeting Log and its Raw_Notes folder).
In-house programSame fields as above, but Theme* adds Cross_Thematic, use it only when the program can't reasonably be assigned to Education or Democracy.
PolicyPolicy name*, used exactly as typed.
Formal governance meetingForum*: Board, Leadership Team, All Team, or Offsites, only formal institutional forums, Concept Review and Investment Committee stay with the project · Meeting date*, the year folder is derived from this date.

*Required. Owner, country/geography, and strategic focus are recorded as metadata in the Master Registry and never shape the folder path, unlike Theme and Meeting log year, which do.

Before anything is created, Preview shows the exact destination path in RADAR and the complete planned folder tree, built directly from this Routing Dictionary. If something looks off, this is the moment to go back and adjust Details, nothing exists in Drive yet.

Confirm spells out exactly what's about to happen, for example: "You are about to create 4 new items in RADAR: 03_INSTITUTIONAL/00_POLICIES/Travel Policy." A few guarantees apply every time:

GuaranteeWhat it means
Nothing existing is touchedNothing is deleted, moved, or renamed, and no permissions are changed.
No automatic rollbackIf part of the operation fails, whatever was already created is left in place and reported.
Safe to retryRunning it twice creates nothing new.

You have to actively check a confirmation box before "Create structure" becomes clickable.

Result lists every item actually created, with an "Open folder in Drive" link straight to the new structure. Some structure types, Policy, Formal governance meeting, and Annual OKR cycle among them, don't get a Master Registry record, that registry is only for Pipeline, Portfolio, Venture Building, and In-house objects.

If a real Drive item is listed here, it exists, no second pass needed.

Which one do I need? Use Classify when you already have a file and need to know where it goes. Use Create Structure when the folder doesn't exist yet and needs to be built the official way, instead of copying an old one by hand.
